## 设计要点

- **平面设计风格**：纯色块 + 实线描边 + 硬投影，没有渐变、毛玻璃、发光
- **涨粉动画**：只有变化的那几位数字向下翻滚滚入；账号卡整体闪一下粉色；弹入绿色「+N」徽章；浏览器标签标题也会短暂显示「涨粉 +N」
- **低频轮询防风控**：默认 **90 秒**一次（可在设置里改成 60–180 秒），实际触发时间在设定值上 **±20% 随机抖动**，不是死板的固定节奏；失败时按 10s→20s→…最多 5 分钟退避重试
- **开机即显示**：上次的粉丝数、昵称、头像会缓存，重新打开先显示旧数据再静默更新，不会白屏
- **OLED 防烧屏**：一个开关搞定纯黑背景 + 内容定时微位移 + 亮度下调（见下节）

## OLED 防烧屏

面板里的「**OLED 防烧屏**」开关，打开后同时启用三层防护。OLED 屏幕长期显示静态画面会烧屏，看板又是 7×24 小时亮着的典型场景，所以这个开关对 OLED 手机很有必要。

### 1. 纯黑背景 + 去掉卡片填充色

- 背景 `#000000`（OLED 上黑色像素**完全不发光**，既省电又不老化）
- 卡片、按钮、状态胶囊的填充色全部改透明，只留细描边 —— 填充色会让整块区域持续发光，是烧屏的元凶
- 连浏览器过度滚动区域也是黑的（`html`/`body` 都设成纯黑）

### 2. 内容定时整体微位移

每 **45 秒**把整个看板（`.stage`）挪一次位置，在 **10 个预设坐标**里轮换，每次再叠加 ±1.5px 随机抖动：

```
横 -8~9px，纵 -8~8px（含抖动最大 10.5px）
45 秒一换 → 7.5 分钟走完一轮，同一像素不会长时间常亮
最大位移 10.5px < 页面内边距 14~16px → 不会露出边缘
```

实现细节：

- 用 `transform: translate3d()` 而不是 `margin/left`，**不触发重排**，几乎零开销
- 用「小幅随机跳变 + 0.45s 过渡」而不是平滑滚动：平滑动画会让 GPU 一直活跃反而更费电，跳变是一瞬间的事
- **页面切到后台时不折腾**（`visibilitychange` 判断），不浪费电
- 觉得挪得太勤/太慢：配置文件里加 `"pixelShiftSec": 90`（最小 10 秒）

### 3. 亮度整体下调

打开时默认把整体亮度降到 **85%**（`filter: brightness(0.85)`），直接降低发光强度 → 延长寿命。

- 用的是 `filter`，和数字缩放用的 `zoom`/`transform` **互不冲突**
- 想更暗/更亮：配置文件里加 `"dim": 0.3`（0 ~ 0.6，0 表示不调暗）

### 4. 纯黑下的可读性（对比度）

纯黑背景上细描边原本几乎看不见（对比度只有 1.84:1），所以 OLED 主题的描边和次要文字特意调得比深色主题更亮：

| 元素 | 颜色 | 对比度 | 等级 |
| --- | --- | --- | --- |
| 主文字（粉丝数） | `#f2f5fa` | 19.22:1 | AAA |
| 次要文字 / 昵称签名 | `#aeb6c4` | 10.29:1 | AAA |
| 描边 / 网格线 | `#6f7a8c` | 4.84:1 | AA |
| 涨（折线、徽章） | `#26e0a6` | 12.30:1 | AAA |
| 跌（折线） | `#ff7b84` | 8.42:1 | AAA |
| 强调粉 | `#fb7299` | 7.97:1 | AAA |

描边从 1.84:1 提升到 4.84:1（**2.6 倍**），次要文字从 5.44:1 提升到 10.29:1。

走势图顶部说明文字、时间范围按钮也一并调亮；折线的颜色**硬编码为十六进制**而不是 CSS 变量，因为 SVG 属性里用 `var()` 在部分浏览器不生效。

### 主题切换

右上角 ◐ 按钮现在**三态循环**：`深色 → 浅色 → OLED`。
手动切到 OLED 时开关自动打开；用开关退出 OLED 时会回到深色主题，两处状态永远一致，不会出现"开关开着但背景不是黑的"这种矛盾。

## 最新作品（标题 + 播放量）

看板上会显示**最近发布的 3 个视频**，纯文字：标题 + 当前总播放量（过万自动显示成 `1.2万`）。可用面板里的「显示最新作品」开关关掉。

### 为什么必须通过 server.js

拉取视频列表比拿粉丝数难得多，实测结论：

| 接口 | 结果 |
| --- | --- |
| `x/space/getSubmitVideos`（老接口） | 已下线，404 |
| `x/space/wbi/arc/search`（官方视频列表） | **-412 请求被拒绝** —— 这个接口风控极严，本机 IP 一请求就封 |
| `x/space/stat/history` 等历史数据接口 | 404 / -403 权限不足 |
| `x/polymer/web-dynamic/v1/feed/space`（**动态**接口） | **可用**，但要求 WBI 签名 |

所以 `server.js` 里实现了 **WBI 签名**（B站 2023 年加的鉴权：取 `nav` 接口的 `img_key`/`sub_key` → 按固定置换表生成 mixinKey → 参数排序拼接后 MD5）。签名算法我用「视频详情接口」验证过是对的（返回 `code=0`）。

### 防封禁的层层保护

因为限流是**按 IP** 的（我自己在调试时就被封过一次，连粉丝数接口都一度受影响），服务端做了：

- **30 分钟结果缓存**：正常情况半小时才请求一次接口
- **磁盘持久化**（`cache-videos.json`）：重启服务不丢，也不会因为重启就重新拉
- **命中 412/352 就指数退避**：15 分钟 → 30 → 60 → 120 分钟，退避期间**完全不碰接口**
- **退避期间回退上次的好数据**，并在界面上标注「数据于 X 分钟前获取（接口限流中）」
- 前端也做 **30 分钟节流**，两次请求之间不重复问

> 意思是：视频信息最多可能滞后半小时——对「最新作品」这个用途来说完全可以接受，换来的是不会被封。

### 界面上的排版优先级

横屏（尤其是手机横屏只有 360px 高）空间很紧，所以做了**预算分配**，空间不足时按优先级依次让位：

```
数字 > 走势图 > 账号卡 > 视频列表
```

实测各尺寸（数字取 398,178）：

```

412×915  手机竖屏   字号 79px  视频 136px  图表 420px  占用 100% ✓
780×360  手机横屏   字号 74px  视频让位     账号卡让位   图表 46px   占用 92% ✓
1280×720 电脑横屏   字号 126px 视频 136px  图表 102px  占用 96% ✓
```

## 走势图的数据是怎么来的

**B站没有公开的历史粉丝数接口**（`x/space/upstat`、`x/space/stat/history` 等要么返回空对象、要么 `-403 访问权限不足`，那些曲线图需要登录态），所以曲线只能由**本机逐步积累**，存在浏览器的 `localStorage` 里，刷新、关页面、重启浏览器都不会丢。

采样策略兼顾两头：

- **前 15 分钟密采样**：约 45 秒一个点 —— 打开几分钟就能看到真实曲线
- **之后稀采样**：10 分钟一个点 —— 为天/周级别保留跨度
- 粉丝数一变就立刻记一个点（不等采样间隔）
- 保留 14 天、最多 5000 个点（约 150KB）

实测各场景能攒到多少点（每 90 秒轮询一次）：

```
第一次打开看 5 分钟               →   4 个点  ✓ 能画出曲线
打开 3 次 × 每次 5 分钟           →  12 个点  ✓
打开一次看 1 小时                 →  25 个点  ✓
挂机 12 小时                     → 237 个点 (5.9KB) ✓
一周里每天看 30 分钟              → 107 个点 (2.8KB) ✓
```

> 只有 1 个点时也会画出**一条水平线 + 端点**，并在标题栏显示「已记录 N 个点 · X 分钟前起」，不会一片空白。
> 早期版本固定 10 分钟才采一个点，导致"每次打开图表都是空的"——这是修掉的一个真 bug。


## 横竖屏自动适配

页面会**自动检测屏幕方向并切换两套排版**，你把手机横过来放，它就变横版布局，转回竖屏自动切回：

| | 竖屏（portrait） | 横屏（landscape） |
| --- | --- | --- |
| 结构 | 单列纵向流：账号 → 数字 → 涨跌 → 走势图 | 左＝账号+走势图+状态，右＝**超大数字**（独占宽栏） |
| 数字大小 | **实测后自动缩放**，撑满可用宽度 | 同上，按右栏可用宽高取最优 |
| 走势图 | 弹性拉伸，吃掉数字下方的剩余高度 | 弹性拉伸，与右栏数字等高 |
| 涨粉徽章 | 压在数字右上角（避免超出窄屏） | 移到数字右侧 |
| UID 标签 | 隐藏（竖屏太窄，UID 见底部信息行） | 显示在昵称右侧 |

判定逻辑：

- 用 **宽高比**判断（`宽 > 高 × 0.97`），而不是 `screen.orientation`——这样对折叠屏、分屏、系统旋转锁定都更可靠
- 阈值 0.97 带一点迟滞，正方形窗口不会来回抖动切版
- 手机地址栏收起/展开也会触发 `resize`，所以做了 **150ms 去抖**，避免中间状态闪烁
- 切换后会**自动重画走势图**（SVG 是 `preserveAspectRatio="none"`，容器变形后需要重绘）
- 另外用 `@media (max-aspect-ratio:1/1)` 做了纯 CSS 兜底，即使 JS 没跑到也能正确排版

### 数字大小是实测出来的，不是估算的

手机字体的数字宽度千差万别，用 `font-size: 26vw` 这类估算法必然在部分机型上溢出。所以改成：

1. CSS 里把基准字号固定为 `100px`，于是「量到的像素尺寸」直接就是比例
2. JS 量出数字的**真实渲染尺寸**和可用宽高。可用高度是**自己算**的（栏高 − 同栏其它元素高度 − 间距），不用容器当前高度——那个值本身受当前缩放影响，会算错
3. 用 `zoom` 缩放到刚好撑满——布局尺寸同步缩放，flex 居中即天然居中；不支持 `zoom` 的浏览器退回 `transform: scale()` 并用负 margin 抵消空间
4. 数字设置 `white-space: nowrap`，**物理上不可能换行溢出**
5. **兜底实测**：如果极端尺寸（手机横屏只有 360px 高）下总算下来仍放不下，就实测量一遍，等比缩小数字——宁可数字小一点，也绝不溢出屏幕
6. 转屏、地址栏收放、字体加载完成都会重新适配（`ResizeObserver` + 窗口事件）

> 想微调留白：配置文件里加 `"fill": 0.94`（0.5~1.0，越小留白越多），默认 0.94。

### 走势图高度与比例

- **高度有上下限**：竖屏 `clamp(160px, 30vh, 290px)`，横屏 `clamp(120px, 36vh, 230px)`；矮屏（≤460px 高）降到 46px 让位
  —— 早期版本没设上限，在电脑竖屏窗口里图表会长到 700px、把数字挤小，这是修掉的一个真 bug
- **比例不会失真**：SVG 用的是 `preserveAspectRatio="none"`，所以 `viewBox` 直接取 `getBoundingClientRect()` 的真实渲染尺寸，
  做到 **1 个 viewBox 单位 = 1 个 CSS 像素**。否则容器一变高，折线会被纵向拉伸、方块点变成竖长条、微小波动看起来像剧烈起伏
- **顺序**：先定数字 → 再按定稿尺寸分配图表高度 → 最后按图表真实尺寸重画折线（`refitAndRedraw`）

**为什么竖屏走势图那么大？** 7 位数字撑满屏宽后，纵向必然剩 60% 以上——这是单行 7 位数的物理限制（每位最宽只能占屏宽 ÷ 7）。与其留白，不如让走势图长高填满，整屏更像一块完整看板。不想要就让 `fill` 变小。

实测纵向利用率（模拟计算，数字取 398,178）：

```
竖屏 360×640   字号 68px   图表 243px   占用 89% ✓
竖屏 390×844   字号 74px   图表 321px   占用 76% ✓
竖屏 412×915   字号 79px   图表 348px   占用 73% ✓
电脑竖屏窗口 900×1100  字号 176px  图表 418px  占用 81% ✓
宽窗口竖屏 1200×900    字号 237px  图表 342px  占用 99% ✓
横屏 1280×720  字号 126px  图表 274px   占用 100% ✓
横屏 780×360   字号 74→55px（兜底压缩）  图表 46px  占用 100% ✓
```

## 二、开始使用

### 第 1 步：把 `index.html` 弄到手机上

手机还没连电脑，四选一即可：

- **微信/QQ 传文件**：发给自己 → 手机上点开 → 选「用浏览器打开」
- **网盘**：上传后手机端下载，再用浏览器打开
- **数据线**：以后连上电脑时，复制到手机 `Download` 文件夹，用文件管理器点开
- **跑本地服务**（推荐，见第 3 步）：手机浏览器输入电脑的局域网地址直接访问

> 用浏览器「打开本地文件」时，部分浏览器会限制联网取数（见第 4 步的排错）。

### 第 2 步：设置 UID + 添加到主屏幕

1. 页面会自动弹出设置面板（没有就点右上角 **⚙**）
2. 填 **B站 UID**：打开 UP 主主页，看地址栏 `space.bilibili.com/`**`546195`** 这串数字
   - 支持多个，用英文逗号隔开，例如 `546195,703007996`，会按顺序轮播
   - 想先看看效果，点「**演示一次**」——不联网，用假数据跑一遍
3. 点「**保存并刷新**」，出现粉丝数就成功了
4. 手机浏览器菜单 → **添加到主屏幕**，之后从桌面图标启动（没有地址栏，最像原生 App）

### 第 3 步：让手机一直亮着（关键）

看板要 24 小时显示，必须让屏幕不熄：

- **安卓**：设置 → 显示 → 息屏时间 → 选「永不」；或开发者选项里打开「充电时不锁定屏幕」
- **iPhone**：设置 → 显示与亮度 → 自动锁定 → 「永不」
- 插上充电器，把手机横放或竖放固定在支架上
- 页面内的「保持屏幕常亮」开关会调用浏览器 Wake Lock 接口，属于额外保障；**系统层面的息屏设置才是决定性的**
- **OLED 屏幕**建议开启面板里的「纯黑背景」并适度调低亮度，长期显示更省电、更不易烧屏

### 第 4 步（可选）：跑本地服务，取数最稳

在电脑上（Node 18+）：

```powershell
cd C:\Users\weeazn\Downloads\B站显示粉丝数
node server.js
```

输出会打印地址，例如：

```
本机打开：  http://127.0.0.1:8787
手机打开：  http://192.168.1.5:8787
```

手机连**同一个 WiFi**，浏览器直接打开 `http://192.168.1.5:8787` 即可。
如果手机端是本地文件打开的，就在 **⚙ → 高级选项 → 自建代理地址** 填 `http://192.168.1.5:8787`，取数会走电脑转发，最不容易失败。

> 首次运行 Windows 会弹防火墙提示，选「允许访问」（专用网络即可）。
> 电脑关机后手机页面仍能继续用它自己的方式取数，只是不再走代理。

## 四、工作原理

```
手机浏览器看板  ──① 自建代理（若已填）──►  你的电脑  ──►  api.bilibili.com
              ──② 官方接口 JSONP 直连 ──────────────────►  api.bilibili.com
              ──③ 公共 CORS 代理（兜底）────────────────►  api.bilibili.com
```

依次尝试，哪个通用哪个，页脚会显示本次用的数据源：

- **`x/relation/stat`** → 粉丝数、关注数（数据主体）
- **`x/web-interface/card`** → 昵称、头像、签名（取不到也不影响粉丝数显示）

细节：

- **刷新间隔**默认 90 秒，可在设置里改（10 秒 ~ 1 小时，建议 60–180）。实际触发时间会 **±20% 随机抖动**，避免固定节奏被判定为脚本；`server.js` 侧还有 8 秒缓存，防止抖动手速刷爆接口
- **失败自动退避**：连续失败会按 10s → 20s → 40s → …最多 5 分钟重试，断网恢复后自动继续
- **走势图与涨跌**：每 45 秒 ~ 10 分钟记一个点（前 15 分钟密采样），存手机本机 `localStorage`（保留 14 天），24 小时 / 7 天涨跌由本地历史算出，不需要任何后端
- **多账号**：每 `刷新间隔` 秒轮播下一个账号，并顺手预热再下一个
- **不显示具体数字**：面板里的「隐藏数字」开关，只呈现涨跌趋势
- **头像兜底**：头像加载失败时用昵称首字生成平面色块头像，不会开天窗

## 五、把默认值写进文件（做批量/成品机）

打开 `index.html`，最上面有一段 JSON，改完保存即可，不用再进设置面板：

```json
{
  "uids": "",
  "intervalSec": 90,
  "showChart": true,
  "theme": "dark",
  "server": "http://192.168.1.5:8787",
  "demo": false,
  "wakeLock": true,
  "immersive": false,
  "hideCount": false

```

设置面板里的「配置快照」会自动生成这段 JSON，点「复制配置」直接粘回去就行。
（手机上改过的设置存在 `localStorage`，会覆盖这段默认值；想让它重新生效，在面板里保存一次新的即可。）

## 六、排错

| 现象 | 原因与处理 |
| --- | --- |
| 顶部一直「连接失败」，底部显示超时 | ① 本地文件打开时浏览器不允许直连，改用 `node server.js` 后访问 `http://电脑IP:8787`；② 手机网络受限（公司/校园 WiFi），换成手机流量或自建代理；③ 页脚会显示三种方式各自的失败原因，按提示判断 |
| 提示 `code=-404` | UID 不存在，检查数字对不对 |
| 提示 `code=-412` / `-352` | 被 B 站风控限流。把刷新间隔调到 180 秒以上，等十几分钟；或改用 `server.js`（带浏览器请求头 + 8 秒缓存，明显更稳） |
| 只显示数字，没有头像昵称 | 正常。`card` 接口偶尔取不到，粉丝数不受影响 |
| 走势图只有一条直线 | 刚用不久，历史点还太少；多跑一会儿就有了 |
| 屏幕还是会黑 | 是**系统**在息屏，去系统设置里把自动锁定改成「永不」，页面内的常亮开关管不了系统策略 |
| 电脑休眠后手机页面上不了代理 | 正常，代理只是加速/兜底；页面检测到失败会自动降级到直连 |

## 七、合规与注意

- 用的是 B 站**公开接口**，只读、不登录、不涉及任何账号隐私
- 默认 90 秒轮询 + ±20% 随机抖动，每小时约 40 次请求，属于正常看板流量；请不要把间隔改到 30 秒以下
